Reduced Motion учитывает пользовательский выбор и Windows. Виртуализация сохраняется; возвращающиеся старые строки не получают повторную entry-анимацию.
- **Настройки → Безопасность чата:** независимые переключатели фильтрации, автомодерации и скрытия ссылок зрителей; выбор режима команд, краткое описание наказания и кнопка «Настроить безопасность чата». В редакторе — вкладки «Запрещённые слова», «Лёгкая токсичность», «Исключения», поиск, добавление обычной фразы, перенос между категориями и удаление. Наказания и правила платформ раскрываются отдельно. Раздел «Команды и ссылки · подробно» содержит префиксы, subscriber/member opt-in и доверенные ID. Experimental открывает «Добрый чат» с готовыми и собственной заменой.
- **По умолчанию:** фильтрация и автомодерация включены; soft заменяется на `****` без наказания; blocked скрывает сообщение целиком и запрашивает timeout 3600 секунд. При отсутствии прав/подключения, read-only источнике или защищённом пользователе фильтрация продолжает работать, действие пропускается с причиной.
- **Чат:** небольшая метка категории, результат действия и «Показать оригинал». Оригинал запрашивается отдельным защищённым IPC и появляется только в локальном диалоге. ПКМ позволяет открыть оригинал, добавить слово, исключить сработавшее правило или изменить его категорию. Автоматические события попадают в существующую историю модерации.
- **OBS:** sanitization выполняется в main process перед публикацией и перед начальным/повторным snapshot. Public DTO не содержит оригинала, safeChat-аннотаций или ID правил. Отдельно обработаны fragments, emote alt, reply, имена/подписи и текст суммы. Preview использует тот же display message/renderer; демонстрационные сообщения проходят тот же engine.

Команды с `!` по умолчанию заменяются на `***`; доступны показ полностью и скрытие. Ссылки обычных зрителей удаляются без остального текста. Владельцам, модераторам, VIP, подтверждённым ботам и явно доверенным ID ссылки разрешены; подписчикам/участникам — только при opt-in. ПКМ по сообщению со скрытой ссылкой позволяет добавить отправителя в доверенные. Команды/ссылки сами по себе не наказываются. Пустой результат не попадает в OBS/preview, локально доступен оригинал. Общий модуль `shared/displayPolicy.ts` используется внутри Safe Chat; старые `hideCommands` переводятся на глобальный режим с default mask, отсутствующие поля settings получают defaults без сброса профилей.

Проверки: **130 unit/integration-тестов в 17 файлах**, typecheck, build, lint, test:desktop, test:appearance, test:oauth, test:phase4, test:motion, test:safechat — PASS. В Electron и OBS-странице Edge проверены команды, ссылки, пустые строки, доверенный пользователь, raw WebSocket без оригиналов и безопасный вывод HTML-подобного текста. OAuth использует mock provider; реальные Twitch/YouTube moderation permissions и нативный OBS не считаются проверенными этим прогоном. Пользовательские `.env` и база данных не сбрасывались: desktop-тесты используют отдельные каталоги.

Ограничения: начальный словарь намеренно небольшой и редактируемый; фильтр не обещает обнаружение всех языковых обходов. Fuzzy matching и случайная замена не добавлены. Новый редактор Safe Chat пока на русском; полная локализация старого и нового интерфейса не заявляется. Исходящий rate-limit — максимум два автоматических действия в секунду; очередь до 100 сообщений, повторное действие для одного пользователя — не чаще раза в 30 секунд. Пропуск виден в чате/истории. Изменение словаря пересчитывает отображение буфера, но не наказывает старые сообщения задним числом.

## 2. Что представляет собой приложение

StreamChat — локальное Windows-приложение для объединения Twitch- и YouTube-чата, работы со зрителями и вывода сообщений в OBS. Интерфейс, настройки, профили и локальная история принадлежат одной desktop-программе. Twitch/Google подключаются напрямую из основного процесса приложения.

Техническая основа: Electron, React, TypeScript, Vite, Zustand, SQLite в отдельном worker и виртуализация списка сообщений. Слои разделены: интерфейс обращается к `ChatBackend`, платформенные адаптеры приводят события к общим моделям, main-процесс занимается сетью, OAuth, хранением и локальным overlay-сервером.

Глобальный буфер чата ограничен 2 000 сообщений. Виртуализация не создаёт в DOM все сообщения одновременно. Тексты переписки не сохраняются как полный долговременный архив; сохраняются настройки, аккаунты, профили, агрегаты зрителей и история действий модерации. Данные demo отделены от реальных данных.

## 3. Что сделано по функциям

### Twitch и YouTube

- Реализован вход Twitch через системный браузер и Device Code Flow для Public client.
- Реализован вход Google через системный браузер, PKCE, проверку state и локальный callback на случайном порту.
- Токены сохраняются через Electron safeStorage; есть обновление токенов и восстановление сессии.
- Twitch использует EventSub/Helix для чата и доступных аккаунту действий.
- YouTube использует выбор активной трансляции и gRPC `streamList` с продолжением по page token.
- Поддержаны отправка, удаление, timeout, ban/unban с учётом capabilities и ограничений платформ. Для YouTube сохраняются необходимые идентификаторы ban resource.
- Есть отмена входа, отключение, повторное подключение, выход из аккаунта и отображение ошибок.

### Дополнительные каналы по ссылке

Рядом с входом Twitch/YouTube добавлены поле адреса и кнопка «Добавить чат». Можно хранить до 12 дополнительных ссылок одновременно. Ссылки сохраняются после перезапуска, не заменяя основной OAuth-аккаунт.

Twitch принимает ссылку на канал или popout/embed-чат и подключается гостем без входа. YouTube принимает @handle, channel ID, поддерживаемые старые `/user/`-адреса, ссылку на видео/эфир или `live_chat`. Для YouTube в этом режиме нужен отдельный `YOUTUBE_API_KEY`.

Все подключения по ссылке работают только на чтение. Подпись «Модерация невозможна» видна в форме и карточке; отправка и модерация запрещены также на уровне backend. Есть удаление отдельного канала и защита от повторного добавления канонически одинакового адреса.

### Оформление и OBS

Сохранены семь базовых стилей, локальные профили и единый renderer. Основные настройки упрощены: пользователь выбирает размер текста, плотность и понятные переключатели. Технические параметры перенесены в сворачиваемый раздел.

Локальный сервер выдаёт защищённый URL для каждого сохранённого профиля. OBS получает начальные сообщения и дальнейшие изменения по WebSocket. Preview отражает редактирование сразу; открытый OBS-источник получает новую конфигурацию после сохранения профиля.

### Последнее исправление Google OAuth

Прежняя белая страница сообщала о получении авторизации до обмена кода на токены и сохранения канала. Поэтому пользователь мог видеть успешный возврат, хотя подключение затем завершалось ошибкой.

Теперь страница отображает ожидание, затем успех только после сохранения аккаунта либо понятную ошибку. Отдельно распознаются требование Client Secret, неверные данные OAuth-клиента и выключенный YouTube Data API. Отсутствие аватара не мешает добавлению канала.

Кнопка возврата восстанавливает свёрнутое окно StreamChat и переводит на него фокус, затем вызывает закрытие вкладки. Если браузер запрещает закрытие, остаётся подсказка закрыть вкладку вручную. Страница не получает токены; код авторизации убирается из адресной строки. Локальная сессия страницы ограничена по времени.

## 4. Подробное описание интерфейса

### 4.1. Общий вид и навигация

Основной визуальный стиль — тёмная рабочая панель с зелёным акцентом. Фон почти чёрный (`#111314`), карточки немного светлее (`#191c1e`), границы тонкие серые (`#292d30`). Основной текст светлый, второстепенные подписи приглушённые. Акцент по умолчанию — `#b9f36b`.

Используется Segoe UI с запасными Arial/sans-serif. Кнопки и поля компактные, со скруглениями, линейными иконками и видимым состоянием фокуса. Акцент выделяет основные действия, выбранные элементы, checkbox и sliders. Disabled-контролы становятся полупрозрачными.

Сверху расположена шапка: логотип `streamchat`, метка PREVIEW 0.3, подпись «ЛОКАЛЬНО», Twitch и YouTube с индикаторами соединения. Индикатор платформы показывает наличие подключённого источника; при включённом demo учитываются и тестовые подключения.

Слева — сворачиваемая навигация:

1. «Чат».
2. «Аккаунты».
3. «Оформление».
4. «Зрители».
5. «Настройки».

Активный раздел выделяется. Внизу боковой панели находятся приглашение попробовать тестовый чат, переход к Developer tools и подпись Local backend. При сворачивании остаются иконки.

Внизу окна — строка состояния: число подключений, включён/выключен demo, подпись о локальной SQLite и кнопка запуска/остановки demo. Эта кнопка управляет тестовыми источниками, а не всеми реальными подключениями.

Ошибки дополнительно появляются в закрываемом уведомлении. Основное окно создаётся размером 1440×960, минимально — 900×640. Сетка и ширины панелей адаптируются к доступной ширине; есть настройка масштаба интерфейса.

### 4.2. Первый запуск

Поверх рабочего пространства открывается приветственная карточка «Ближе к вашему чату». В ней есть переходы к подключению Twitch и YouTube, основная кнопка «Попробовать демочат» и действие «Пропустить пока».

Демочат запускается без аккаунтов и ключей. Пропуск открывает пустое рабочее пространство. Выбор сохраняется, поэтому приветствие не требуется проходить при каждом запуске.

### 4.3. Раздел «Чат»

Основная область содержит заголовок «Единый чат» со счётчиком сообщений. Ниже расположены вкладки «Все платформы», Twitch, YouTube и список типов событий: все события, сообщения, донаты, подписчики. Центр занимает лента чата. В зависимости от выбранного стиля сообщение может содержать аватар, иконку платформы, имя, значки, время и текст с emotes. Длинные имена и слова переносятся; список виртуализирован.

### 4.4. Карточка зрителя

В карточке видны аватар либо инициалы, отображаемое имя, платформа, username, ID и значки. Ниже — локальное количество сообщений, первый и последний визит; при timeout отображается оставшееся время.

Действия зависят от прав аккаунта и состояния соединения: длительность timeout из готового списка или собственное время, причина, timeout, постоянный бан с подтверждением, снятие блокировки и удаление сообщения. Дополнительно доступны ответ с подстановкой имени, копирование текста и копирование имени.

История модерации раскрывается отдельно. Недоступные действия скрываются либо отключаются. Для demo действия локальные; для авторизованного аккаунта используются платформенные API. Для read-only-ссылок прав на модерацию нет.

### 4.5. Раздел «Аккаунты»

Экран состоит из карточек Twitch и YouTube. В каждой показаны иконка, название платформы, описание подключения и кнопка входа. У Twitch есть checkbox «Запросить права модерации».

Рядом находится форма «Дополнительный канал по ссылке»: поле адреса, кнопка «Добавить чат» и предупреждение «Модерация невозможна». Для Twitch поясняется гостевое чтение, для YouTube — необходимость API key. При недостатке места форма переносится внутри карточки.

Во время OAuth отображается статус ожидания, у Twitch — код входа, если он выдан. Авторизацию можно отменить. Ошибки конфигурации и входа показываются рядом с нужной платформой.

Каждый добавленный источник имеет собственную карточку: имя, username, аватар при наличии, индикатор соединения, текущий канал/эфир и ошибка. Доступны Reconnect и Disconnect. У OAuth-аккаунта есть Logout с подтверждением; у ссылки — «Удалить канал» с подтверждением.

У авторизованного аккаунта можно запросить список каналов/трансляций и выбрать нужный пункт. Для Twitch также доступен ввод логина канала. YouTube OAuth в текущей реализации ориентирован на активные трансляции своего канала; для чужого публичного эфира предусмотрены ссылки.

У источника по ссылке виден сам адрес и пометка «Только чтение». Для гостевого Twitch отдельно указано, что статус видеотрансляции не проверяется. Технические сведения — ID, авторизация, transport, scopes и код ошибки — убраны под «Подробности аккаунта».

## 5. Auto-режим и совместимость профилей

Вычисления вынесены в `src/shared/chatAppearance.ts`. Используются типы `AutoValue<T>`, `ChatAppearance`, `MessageDensity` и версия конфигурации appearance 1. Auto пересчитывается при изменении размера текста или плотности; Manual сохраняет выбранную величину.

| Текст 14 px                    | Компактно | Обычно | Просторно |
| ------------------------------ | --------- | ------ | --------- |
| Аватар                         | 29 px     | 34 px  | 38 px     |
| Межстрочный интервал           | 1,33      | 1,45   | 1,60      |
| Интервал сообщений             | 6 px      | 11 px  | 16 px     |
| Вертикальный внутренний отступ | 4 px      | 7 px   | 10 px     |

Автолимит учитывает высоту контейнера, текст, плотность и предполагаемую высоту сообщения. Это оценка, а не точное измерение каждой строки. Он не меняет глобальный буфер 2 000 сообщений.

При чтении старого профиля явно сохранённые avatarSize, lineHeight, messageSpacing и maxMessages переходят в Manual; отсутствующие значения — в Auto. Остальные параметры сохраняются. Старые maxLength/multiline допускаются при чтении, но вывод использует перенос и ограничение строк. Нормализация происходит на уровне JSON, не требует изменения старых SQL-миграций и не переписывает исходный профиль просто при чтении.

## 6. Текущая ситуация с пользовательским YouTube

Client ID Twitch и Google внесены в локальный `.env`. Пользователь также добавил Google Client Secret; наличие непустого значения проверено без вывода секрета.

Первоначальная ошибка Google 403 относилась к доступу тестировщиков. В следующей попытке браузер дошёл до callback, но журнал приложения зафиксировал `REQUEST_REJECTED`, а канал не появился. В тот момент Client Secret отсутствовал; прежняя общая диагностика не сохранила точную причину отказа провайдера.

После добавления секрета и исправления callback выполнены автоматические проверки успешного и неуспешного сценариев. **Результат повторного настоящего входа пользователя после этих изменений пока не подтверждён.** Следующий практический шаг — перезапуск через BAT и повторное подключение YouTube, после которого нужно убедиться, что карточка канала появилась. Даже без активного эфира успешно авторизованный канал должен сохраняться в «Аккаунтах»; получение live chat требует доступного эфира.

Google OAuth Client ID и YouTube API key выполняют разные задачи. Client ID относится к входу пользователя; отдельный API key нужен для реализованного чтения публичного YouTube-чата по ссылке без OAuth. Наличие такого ключа после последних действий пользователя не проверялось.

## 8. Ограничения и следующие шаги

1. Завершить реальный вход YouTube после перезапуска и проверить появление аккаунта. Затем проверить активный эфир, получение сообщений и разрешённые действия.
2. Пройти полноценную проверку Twitch OAuth, обновления сессии, отправки и модерации с реальными правами.
3. Проверить настоящий YouTube API key для режима по ссылке. Для канала без активного эфира нужен повторный Reconnect после старта; при нескольких эфирах используется прямая ссылка на нужный.
4. Проверить несколько источников одновременно и нативный OBS: подключение, обновление профиля, переподключение и длительную работу.
5. Учитывать ограничения ссылок: YouTube `/c/…` не разрешается; воспроизведение архивного чата не реализовано. Гостевой Twitch не проверяет наличие видеотрансляции.
6. Очень длинное сообщение в режиме «Полностью» может занять высоту overlay; для такого случая доступны 3/5 строк.
7. Привести README, старые подписи фаз, версию пакета и отдельные оставшиеся английские/устаревшие тексты UI к одному состоянию.
8. Отдельно подготовить tray, автозапуск, упаковку Windows, установщик, подпись и остальные релизные функции. Они не считаются готовыми только на основании наличия BAT.
